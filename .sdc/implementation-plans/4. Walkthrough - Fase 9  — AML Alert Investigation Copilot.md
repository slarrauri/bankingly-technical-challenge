## 2. Componentes Construidos

### A. Dominio y Persistencia (`backend/domain/` y `backend/data/`)
- [`models.py`](file:///f:/documents/bankingly-technical-challenge/backend/domain/models.py): Definición de entidades SQLAlchemy (`Customer`, `CustomerKYC`, `Counterparty`, `Transaction`, `AMLAlert`, `AMLPolicy`, `Investigation`, `Recommendation`, `Approval`, `AuditEvent`).
- [`database.py`](file:///f:/documents/bankingly-technical-challenge/backend/data/database.py): Fábrica de sesiones con soporte para PostgreSQL y SQLite in-memory / file.
- [`seed.py`](file:///f:/documents/bankingly-technical-challenge/backend/data/seed.py): Ingesta de 12 perfiles de clientes, 18 contrapartes, 4 políticas institucionales, 12 alertas y 400 transacciones bancarias simuladas desde `data/seed/aml_simulated_transactions_400.csv`.

### B. Herramientas Determinísticas (`backend/tools/`)
- [`schemas.py`](file:///f:/documents/bankingly-technical-challenge/backend/tools/schemas.py): Modelos de entrada y salida Pydantic v2 para cada herramienta autorizada.
- [`summary_service.py`](file:///f:/documents/bankingly-technical-challenge/backend/tools/services/summary_service.py): Cálculo determinístico en Python de variación porcentual de volumen (e.g. `+342%`), ratios de ingreso declarado y detección de contrapartes no habituales (`ADR-005`).
- [`alert_service.py`](file:///f:/documents/bankingly-technical-challenge/backend/tools/services/alert_service.py), [`customer_service.py`](file:///f:/documents/bankingly-technical-challenge/backend/tools/services/customer_service.py), [`transaction_service.py`](file:///f:/documents/bankingly-technical-challenge/backend/tools/services/transaction_service.py), [`policy_service.py`](file:///f:/documents/bankingly-technical-challenge/backend/tools/services/policy_service.py).

### C. Agent Harness & Seguridad (`backend/harness/` y `backend/agent/`)
- [`tool_registry.py`](file:///f:/documents/bankingly-technical-challenge/backend/harness/tool_registry.py): Registro estricto de herramientas de solo lectura. **Sin herramientas de mutación ni ejecución para el LLM (`INV-001`)**.
- [`prompt_engine.py`](file:///f:/documents/bankingly-technical-challenge/backend/agent/prompt_engine.py): Delimitadores `<data>` para aislamiento de memos y notas, neutralizando prompt injection (`INV-006`).
- [`validator.py`](file:///f:/documents/bankingly-technical-challenge/backend/harness/validator.py): Validación estricta de salida estructurada JSON contra el schema `InvestigationResult` con reintentos controlados (`INV-009`).
- [`state_machine.py`](file:///f:/documents/bankingly-technical-challenge/backend/harness/state_machine.py): Bloqueo formal de la transición directa `RECOMMENDATION_READY → EXECUTED` (`INV-010`).
- [`approval_gate.py`](file:///f:/documents/bankingly-technical-challenge/backend/harness/approval_gate.py): Exigencia inquebrantable de registro de aprobación humana previa por analista autorizado (`INV-002`, `INV-003`, `INV-004`).
- [`audit_service.py`](file:///f:/documents/bankingly-technical-challenge/backend/harness/audit_service.py): Auditoría inmutable de eventos regulatorios.
- [`orchestrator.py`](file:///f:/documents/bankingly-technical-challenge/backend/harness/orchestrator.py): Orquestador acotado del ciclo de investigación.

### D. API REST FastAPI (`backend/api/` y `backend/main.py`)
- [`alerts.py`](file:///f:/documents/bankingly-technical-challenge/backend/api/alerts.py): Endpoints `/api/v1/alerts` y `/api/v1/alerts/{alert_id}`.
- [`investigations.py`](file:///f:/documents/bankingly-technical-challenge/backend/api/investigations.py): `/api/v1/investigations/start` y `/api/v1/investigations/{id}`.
- [`decisions.py`](file:///f:/documents/bankingly-technical-challenge/backend/api/decisions.py): `/api/v1/investigations/{id}/decide` y `/api/v1/investigations/{id}/execute`.
- [`main.py`](file:///f:/documents/bankingly-technical-challenge/backend/main.py): Aplicación FastAPI con CORS, auto-seed en startup y montaje de la UI estática.

### E. Consola de Cumplimiento Web (`frontend/`)
- [`index.html`](file:///f:/documents/bankingly-technical-challenge/frontend/index.html): Interfaz del analista con cola de alertas, visor KYC, métricas transaccionales, informe del Copilot, badges de evidencia y modal de confirmación.
- [`index.css`](file:///f:/documents/bankingly-technical-challenge/frontend/index.css): Estética fintech moderna, tema oscuro con glassmorphism y micro-animaciones.
- [`app.js`](file:///f:/documents/bankingly-technical-challenge/frontend/app.js): Lógica reactiva para investigar alertas, inspeccionar evidencia y autorizar decisiones.
