# Plan de Implementación: Carga Dinámica desde SQLite y Feedback Visual de Carga / Investigación

Conectar completamente el Frontend a la base de datos SQLite para eliminar cualquier dato mock/hardcodeado en el perfil KYC y el análisis transaccional, y agregar indicadores de carga (loading states) claros y un overlay central interactivo que simule visualmente las etapas de investigación del Copilot.

## User Review Required
> [!IMPORTANT]
> Se agregará el endpoint `GET /api/v1/alerts/{alert_id}/context` en FastAPI para consolidar los datos de la alerta, el perfil KYC del cliente y el resumen transaccional calculado determinísticamente desde la base SQLite.

## Proposed Changes

### Backend API & Tools

#### [MODIFY] [backend/api/alerts.py](file:///f:/documents/bankingly-technical-challenge/backend/api/alerts.py)
- Agregar endpoint `GET /alerts/{alert_id}/context` que invoque con aislamiento multi-tenant:
  1. `get_alert_service`: Datos de la alerta seleccionada.
  2. `get_customer_profile_service`: Datos del perfil KYC del cliente desde SQLite.
  3. `get_transaction_summary_service`: Métricas calculadas determinísticamente (volumen 30 días, ratio vs ingresos, contrapartes nuevas, etc.) desde la tabla de transacciones de SQLite.
- Devolver respuesta estructurada bajo el contrato estándar.

---

### Frontend UI & Logica

#### [MODIFY] [frontend/index.html](file:///f:/documents/bankingly-technical-challenge/frontend/index.html)
- Reemplazar los textos estáticos mock por placeholders / skeletons iniciales.
- Agregar un overlay modal central de investigación (`#investigationLoadingModal`) con spinner de alta calidad, barra de progreso y etapas dinámicas:
  - 🔍 *Paso 1: Consultando perfil KYC y registros del cliente en SQLite...*
  - 📊 *Paso 2: Calculando métricas transaccionales y análisis de volumen...*
  - 📜 *Paso 3: Contrastando hallazgos con las Políticas Institucionales AML...*
  - 🤖 *Paso 4: Estructurando reporte explicable y recomendación para el analista...*
- Agregar indicadores de carga para las tarjetas KYC y de transacciones al cambiar de alerta.

#### [MODIFY] [frontend/index.css](file:///f:/documents/bankingly-technical-challenge/frontend/index.css)
- Estilos para el overlay central de investigación (`.investigation-loading-overlay`), animación de escaneo y progreso de pasos.
- Estilos para skeleton loaders / spinner en tarjetas de contexto.

#### [MODIFY] [frontend/app.js](file:///f:/documents/bankingly-technical-challenge/frontend/app.js)
- En `selectAlert(alert)`:
  - Activar estado de carga en tarjetas de KYC y Transacciones.
  - Llamar a `GET /api/v1/alerts/${alert.id}/context`.
  - Renderizar en el DOM los datos reales del cliente (`kycOccupation`, `kycIncome`, `kycFundsSource`, `kycNotes`, `kycStatusBadge`, `volChangeChip`, `recentInflow`, `recentOutflow`, `incomeRatio`, `newCounterparties`).
- En `triggerInvestigation(alertId)`:
  - Mostrar el modal/overlay central de carga con transición animada de los pasos de investigación.
  - Al completar la respuesta del backend, cerrar el modal y renderizar el reporte completo con sus hallazgos, políticas y recomendación.

## Verification Plan

### Automated Tests
- Ejecutar suite de pruebas de FastAPI con `pytest tests/unit tests/integration` para validar que los endpoints y servicios siguen cumpliendo todos los invariantes.

### Manual Verification
- Iniciar el servidor backend (`python -m uvicorn backend.main:app --port 8000`).
- Abrir la interfaz web (`http://localhost:8000/`).
- Navegar entre diferentes alertas en la lista lateral (ej. `AML-001` Martín Pereira, `AML-003` Sofía González, `AML-006` Andrés Molina, `AML-007` Camila Varela) y verificar que:
  1. Los datos de KYC cambien fielmente a los registrados en la DB para cada cliente.
  2. Los datos transaccionales reflejen las sumas y porcentajes reales calculados desde SQLite.
  3. Al presionar "Investigar con Copilot", se despliegue el loading central simulando el proceso de recopilación y contraste antes de mostrar la recomendación final.
