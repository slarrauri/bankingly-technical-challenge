# 5. CUST-004 — Martín Pereira

> Este es nuestro caso central.

```text
Customer ID: CUST-004
Country: Uruguay
Occupation: Software Consultant
Declared Monthly Income: USD 4,500
Risk Level: MEDIUM
KYC Status: VERIFIED
Customer Since: 2022-04-18

Declared Source of Funds:
Professional consulting services
```

### KYC note

```text
Customer indicated that occasional
international consulting projects may generate
additional income.
```

Esto es deliberadamente ambiguo.

La información KYC **permite explicar potencialmente** ingresos extraordinarios, pero no los justifica automáticamente.

Este será el cliente sobre el que construiremos:

- alerta AML    
- nuevas contrapartes    
- incremento transaccional    
- información contradictoria    
- solicitud de documentación

# 14. Algo importante: no agregar "suspiciousness"

No poner en los datos:

```text
is_suspicious: true
```

ni:

```text
expected_aml_decision: ESCALATE
```

Eso pertenece al **evaluation ground truth**, no al dataset operativo.

La separación es:

```text
Operational Data
        │
        ▼
     Agent
        │
        ▼
 Investigation Result
        │
        ▼
Evaluation
        │
        └── Ground Truth
```

Así evitamos contaminar el agente con la respuesta.

---

# 15. Otra decisión importante: KYC ≠ verdad absoluta

El KYC representa **lo declarado y registrado por la institución**.

No significa que:

```text
declared_income = actual_income
```

Por eso podremos crear situaciones como:

```text
KYC:
USD 4,500/month

Transactions:
USD 20,000 incoming
```

Y el agente deberá investigar la discrepancia.

No decir automáticamente:

> "El cliente mintió."
