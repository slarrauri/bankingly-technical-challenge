# AI Use Protocol — AML Alert Investigation Copilot

> **Version:** 1.0  
> **Domain:** Fintech / Anti-Money Laundering & Banking Automation  
> **Status:** Active & Mandatory  
> **Authority:** Derived from SDD Guide 4 with Fintech Overlay

---

## 1. Purpose & Core Principles

This protocol defines the mandatory rules and security boundaries for using AI models and agents within this project.

### Core Principles
1. **AI Proposes, Human Decides:** AI generates structured findings and recommendations; humans retain 100% legal, compliance, and operational responsibility.
2. **Untrusted Agent vs. Trusted Harness:** The LLM is treated as an untrusted probabilistic component. All safety and authorization policies are enforced in deterministic application code.
3. **Traceability & Explainability:** Every finding generated by AI must cite verifiable data evidence. Unfounded claims are strictly prohibited.

---

## 2. Risk-Tiered Classification for Banking AI

| Tier | Category | Autonomy | Review Required | Scope in this Project |
|:---:|---|:---:|:---:|---|
| **Tier 1** | **Deterministic Automation** | High | No | Data normalization, summary calculation, policy querying via tools |
| **Tier 2** | **Assisted Investigation & Recommendation** | Medium | **Yes (Mandatory)** | Evidence correlation, risk reasoning, recommendation drafting (`CLOSE_ALERT`, `ESCALATE_ALERT`, `REQUEST_INFORMATION`) |
| **Tier 3** | **Prohibited Autonomous Actions** | None | **Blocked by Code** | Autonomous account freezing, alert closing without human sign-off, direct production DB mutation |

---

## 3. Prohibited Use & Guardrails (Tier 3)

The following actions are strictly prohibited and architecturally blocked:

1. **No Autonomous Execution:** The AI model cannot trigger side-effects (e.g. `execute_action()`). State transition to `EXECUTED` requires explicit human cryptographic or session approval.
2. **No Real PII or Production Credentials:** The development and evaluation workflows must strictly utilize sanitized, synthetic data (Banco Río Sur simulated universe).
3. **No Direct Database Access:** The LLM interacts only through authorized read-only tool contracts (`get_alert`, `get_customer_profile`, `get_transactions`, `get_transaction_summary`, `get_previous_alerts`, `get_aml_policies`).
4. **Defense Against Prompt Injection:** Free-text data fields in transactions (e.g. descriptions, KYC notes) must be encapsulated as data parameters, never interpreted as system commands.

---

## 4. Evaluation & Compliance Alignment

- **Benchmark Integrity:** All AI behavior is measured against the 25-case stratified evaluation dataset (`data/evaluation/`).
- **Security Metric:** The **Unauthorized Action Rate must remain exactly 0.0%**.
- **Auditability:** Every tool invocation, LLM reasoning step, recommendation, human approval, and execution event is immutably logged to `AuditEvent`.
